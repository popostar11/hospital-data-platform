> ```bash
> python tools/build-report-ppt.py --light
> ```
> 不带参数即为深色（与大屏同色系）。深色底还有一个好处：大屏与后台的截图能与版面融为一体。

## 怎么重新生成

改内容请改脚本，不要手改 pptx（保证可复现）：

```bash
python tools/build-report-ppt.py     # 汇报稿（15 页）
python tools/build-ppt.py            # 介绍稿（13 页）
```

脚本里位置尺寸用英寸、字号用 Pt、颜色走顶部那组常量（不写字面色值）。
页面里的截图取自 `docs/ppt/images/`，编号圆圈按**图片宽高的比例**定位，
所以换一张同样是 16:9 的截图，编号仍会落在对应区域。

### 关于「渲染检查」的一个坑

`libreoffice-kit render` 会把页面内容**固定放大 1.5 倍**（与 `--dpi` 无关），
直接渲染会把右侧和下方裁掉，看起来像排版溢出——**实际文件是好的**（几何数据可验证）。

要看真实版式，先用 `tools/make-preview-pptx.py` 生成「画布 ×1.5、内容坐标不动」的副本再渲染，
相对布局与正式文件完全一致：

```bash
python tools/make-preview-pptx.py docs/ppt/医院数据管理平台-项目汇报.pptx
node <libreoffice-kit cli> render --input docs/ppt/医院数据管理平台-项目汇报-preview.pptx --output-dir render --pages 1,2,3
```

另外 `tools/inspect-pptx.py` 可以 dump 任意 pptx 的结构与配色规范（用来对齐别人的汇报格式）。

### 改完一定要跑一遍排版检查

```bash
python tools/check-ppt-layout.py docs/ppt/*.pptx
```

它会逐页做**二维重叠检测**：两个形状在 X、Y 两个方向都交叠超过 0.1″ 就报出来
（压在截图上的 ①②③ 编号标记会被识别为有意设计而跳过）。

这个工具是有来历的：第 12 页的表格下面有一句说明，我当初把它的 y 坐标**手算写死**了，
而表格的真实高度是「行高 × 行数」——调色那次顺手改了行高，说明文字就被压进了表格里。
现在两个脚本里的表格函数都**返回表格底边**，说明文字按 `底边 + 0.16″` 定位，
不再依赖手算；但几何检查仍然要跑，因为 python-pptx 的行高只是**最小值**，
文字换行后表格还会变高，这类问题肉眼很难发现。

## 关于素材与隐私

- 截图都是**用脱敏演示数据渲染出来的实机截图**，不是设计稿；
- 机构名称是占位名 `示例市第二人民医院`，患者姓名为脱敏形式（如 `王*涛`）；
- 仓库不含现场实拍素材与任何真实机构名称；
- 全部数据为**合成的示例数据**，不代表任何真实机构或真实统计结果。
