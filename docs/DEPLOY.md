# 本地部署手册

> 适用：单机部署（后端一个进程同时托管「管理后台」与「大屏终端」两个前端，只占一个端口）。
> 一键启动脚本会自动完成「装依赖 → 构建 → 导数据 → 起服务」，缺哪步补哪步。

---

## 一、部署形态

```
                    ┌─────────────────────────────────────┐
  浏览器 / 大屏 ───▶ │  单进程 Node 服务（默认 3000 端口）    │
                    │  ├─ /api/v1   后端接口 + SSE         │
                    │  ├─ /admin/   管理后台（静态产物）    │
                    │  ├─ /screen/  大屏终端（静态产物）    │
                    │  └─ /         导航页                 │
                    │  数据：data/hospital.db (SQLite)     │
                    └─────────────────────────────────────┘
```

不需要额外安装 Web 服务器、数据库或运行时——这是刻意的选型结果，见 [adr/001](adr/001-sqlite-instead-of-prisma.md)。

---

## 二、前置条件

| 项 | 要求 | 检查命令 |
|---|---|---|
| 操作系统 | Windows 10/11、Windows Server 2016+ | — |
| Node.js | **≥ 20**（实测 v24） | `node -v` |
| 磁盘 | ≥ 500 MB（含依赖与数据库） | — |
| 网络 | 首次部署需联网下载依赖；之后可完全离线运行 | — |
| pnpm | **不需要预装**，脚本会自动回退到 corepack / npx | — |

> 机器上没装 pnpm 也没关系。`启动.bat` 按 `pnpm → corepack pnpm → npx pnpm@11` 顺序自动选择，实测在只装了 Node 的机器上可正常部署。

---

## 三、一键部署（推荐）

1. 把整个项目目录拷到目标机器（例如 `D:\yiyuanshujuguanlixitong`）
2. 双击 **`启动.bat`**
3. 等待脚本输出完成后，浏览器会自动打开 <http://127.0.0.1:3000/>

脚本会依次做：

```
[1/5] 解析包管理器      pnpm / corepack pnpm / npx pnpm@11
[2/5] 安装依赖          仅首次（node_modules 不存在时）
[3/5] 构建              仅缺产物时（后端 + 两个前端）
[4/5] 导入演示数据      仅首次（data/hospital.db 不存在时）
[5/5] 启动服务          并打开浏览器
```

> ⚠️ **部署路径请使用纯英文**（如 `D:\hospital-platform`）。中文路径会导致两件事出问题：cmd 解析开机自启脚本时按代码页解码而找不到文件；个别 Node 工具链对非 ASCII 路径的兼容性也不稳定。
>
> 当前项目位于 `D:\yiyuanshujuguanlixitong`（纯英文），符合要求。

**停止服务**：双击 `停止.bat`（或直接关掉那个服务窗口）。

## 四、命令行部署

```bash
# 若提示 pnpm 不存在，先执行一次：
corepack enable pnpm

pnpm install
pnpm build
pnpm db:seed        # 首次导入演示数据（5439 条病例）
pnpm start          # 前台运行；Ctrl+C 停止
```

## 五、部署验证

### 1. 冒烟检查

| 地址 | 期望 |
|---|---|
| <http://127.0.0.1:3000/api/v1/health> | `{"code":0,...,"status":"ok"}` |
| <http://127.0.0.1:3000/> | 导航页，两个入口卡片可点 |
| <http://127.0.0.1:3000/admin/> | 登录页（账号 `admin` / `Hospital@123`） |

### 2. 自动化验收（三套，共 61 项断言）

```bash
pnpm verify:api      # 36 项：接口 + 合成数据数值 + 权限
pnpm verify:screen   #  7 项：大屏渲染/脱敏/滚动/截图
pnpm verify:admin    # 18 项：真实登录 + 10 个页面巡检
```

三套脚本只依赖 Node 内置能力（`fetch` / `WebSocket` / `child_process`）+ 本机 Chrome 或 Edge，无需额外安装。

## 七、日常运维

| 操作 | 做法 |
|---|---|
| 启动 | 双击 `启动.bat` |
| 停止 | 双击 `停止.bat` |
| 环境诊断 | 双击 `诊断.bat`（打印运行环境、文件完整性、端口占用、最近日志；排查问题先跑它） |
| 开机自启 | 双击 `开机自启.bat`（写入当前用户「启动」文件夹，**无需管理员权限**） |
| 取消自启 | 双击 `取消开机自启.bat` |
| 查看是否已设自启 | `node tools/autostart.mjs status` |
| 查看启动日志 | `logs\launch.log`（启动器的每一步 + 服务本身的输出都会落盘） |
| 备份数据 | 停止服务后复制 `data\hospital.db`（单文件即全部业务数据） |
| 重置演示数据 | 停止服务 → `pnpm db:reset` → 重新启动 |
| 升级代码 | 停止服务 → 覆盖代码（保留 `data\` 与 `.env`）→ `pnpm install` → `pnpm build` → 启动 |
| 改端口/密钥 | 复制 `.env.example` 为 `.env` 后修改，重启生效 |

> 所有双击脚本在结束时都会**停在「按回车键关闭本窗口」**，不会一闪而过；被脚本/CI 调用时（stdin 被重定向）自动跳过等待，不会卡住自动化流程。无人值守场景可设 `NO_PAUSE=1`。

**日志**：服务日志直接输出在启动窗口；停止窗口即丢失。长期留存请用重定向：

```bat
启动.bat > logs\server.log 2>&1
```

## 八、配置项（`.env`）

复制 `.env.example` 为 `.env` 后按需修改，优先级为 **真实环境变量 > `.env` > 代码默认值**。

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | 3000 | 服务端口 |
| `HOST` | 0.0.0.0 | 监听地址；仅本机访问可改 `127.0.0.1` |
| `JWT_SECRET` | 演示值 | **生产必须替换**，用于签发登录令牌 |
| `CRYPTO_KEY` | 演示值 | **生产必须替换**，用于加密患者姓名/身份证/手机号 |
| `DEMO_MODE` | true | 大屏是否允许匿名只读；生产建议 `false` |
| `CAPTCHA_ENABLED` | false | 登录图形验证码 |
| `DB_FILE` | `data/hospital.db` | 数据库位置，可指向独立数据盘 |
| `SCREEN_CACHE_TTL` | 5 | 大屏聚合缓存秒数 |

> ⚠️ `CRYPTO_KEY` 一旦变更，**已加密的历史患者数据将无法解密**。务必先备份，并做好密钥保管。

## 九、局域网访问

服务默认监听 `0.0.0.0`，同网段设备可直接用 `http://<本机IP>:3000/` 访问。

需要在防火墙放行端口（管理员 PowerShell 执行一次）：

```powershell
New-NetFirewallRule -DisplayName "急救绿道数据平台 3000" -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow
```

查看本机 IP：`ipconfig`（取 IPv4 地址）。

## 十、大屏终端配置（Kiosk）

大屏工控机/一体机建议这样配置，实现「开机即显示、无需人工操作」：

1. 把浏览器设为开机自启，并带上 Kiosk 参数（Chrome 示例，快捷方式目标）：

   ```
   "C:\Program Files\Google\Chrome\Application\chrome.exe" --kiosk "http://127.0.0.1:3000/screen/" --incognito --disable-pinch --overscroll-history-navigation=0 --noerrdialogs
   ```

2. 关闭系统休眠与屏保：`设置 → 系统 → 电源 → 屏幕和睡眠` 全部改为「从不」
3. 用 `开机自启.bat` 让服务先起来（约 10 秒就绪），再把浏览器快捷方式放进同一个「启动」文件夹
4. 隐藏鼠标指针已由大屏页面自身处理（`cursor: none`）

**远程排障**：大屏页支持 `?stream=0` 关闭 SSE 推送（仅用轮询），在排查长连接类问题时有用；也支持 `?screenCode=xxx` 在同一终端切换不同科室大屏配置。

## 十一、故障排查

| 现象 | 原因与处理 |
|---|---|
| 双击 `启动.bat` 一闪而过 | 已修复（脚本结束时会停在等待回车）。若仍闪退，说明 Node 未安装或不在 PATH——手动打开 cmd 执行 `node tools\launch.mjs` 看报错 |
| 双击后提示「端口 3000 已被占用」 | 服务已在运行，直接访问即可；要重启先双击 `停止.bat` |
| 提示 `pnpm 不是内部或外部命令` | `corepack enable pnpm`；或直接双击 `启动.bat`（脚本会自动回退到 corepack / npx） |
| `db:reset` 报 `EPERM` | 数据库文件被服务占用，先 `停止.bat` 再重置 |
| 浏览器打开 `index.html` 是空白 | 这是预期行为，见 [README](../README.md) 第一章的说明，请用 `http://127.0.0.1:3000/admin/` |
| 大屏数字不动 | 检查服务是否存活；大屏右上角会显示「数据重连中…」提示 |
| 局域网访问不了 | 放行防火墙端口；确认 `.env` 里 `HOST` 不是 `127.0.0.1` |
| 开机自启无效 | 项目路径含中文会导致 cmd 找不到脚本，请移到纯英文路径后重新执行 `开机自启.bat` |
| 改了 `.bat` 之后出现莫名其妙的命令报错 | `.bat` 里出现了非 ASCII 字符（**含 `rem` 注释里的中文**）。cmd 按代码页逐字节解析，中文会被拆成语法字符。用 `pnpm verify:bat` 定位，中文提示一律写进 Node 脚本 |
