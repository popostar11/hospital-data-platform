# ADR-002：大屏数据的口径取舍（饼图聚焦病种、底部统计、演示数据自洽性）

- 状态：已采纳
- 日期：2026-10-08
- 相关：`docs/PLAN.md` §5、`apps/server/src/db/seed.ts`、`apps/server/src/modules/screen/screen.service.ts`

## 背景

大屏要**版面与交互 1:1 还原参考大屏**，但还原过程中必须先回答一个口径问题：**同一屏上的环形图与底部统计条，分别统计的是什么？**

这几个面板容易被读成互相矛盾，原因是它们本来就回答不同的问题：

| 面板 | 口径定义 | 说明 |
|---|---|---|
| 环形图（累计患者） | 累计历史病例按病种分组 | 默认聚焦单一病种（创伤），聚焦与否是**可配置项** |
| 底部统计条 | 当前未闭环病例按病种分组 | 与环形图的**时间窗不同**，量级天然不同 |
| 24 小时表格 | 明细窗口（近 24 小时） | 是明细列表，与图表的分组口径本身就不必一致 |

也就是说，这三处数值并不是同一口径的三种表达——把它们当成一个数来交叉核对，前提就不成立。需要的是把各面板的口径各自讲清楚，并让公开版数据按这些口径自洽地构造出来。

## 决策

**版面与交互 1:1 还原参考大屏；数据为合成示例数据，不代表任何真实机构的统计值。** 各面板口径显式定义如下。

### 1. 饼图支持“聚焦病种”（默认 TRAUMA）

`screen_config.pie_disease_code`：

- 有值（默认 `TRAUMA`）→ 饼图只统计该病种，渲染为单色环 + 引线标注数值 + 图例「创伤 数值」；
- 为空 → 饼图按全部病种分组，多色多片，各片按字典色着色。

聚焦是一种**展示口径**而非数据修正：累计值在聚焦与全病种两种模式下都成立，只是回答的问题不同（「累计创伤有多少」vs「累计各病种各有多少」）。改口径只需改这一行配置，不用改前端。

### 2. 底部统计条按「当前未闭环病例按病种分组」输出

口径定为「当前未闭环（仍在绿道中）的病例数，按病种分组」，示例输出：

```
总数：4  创伤：3  胸痛：1
```

总数与分病种之和恒等（3 + 1 = 4），口径自洽；具体病种构成由数据本身决定，不由前端写死。

### 3. 演示数据构造为自洽

种子生成器（`src/db/seed.ts`）按下列目标构造数据，各面板口径互相自洽：

| 指标 | 目标 | 实现方式 |
|---|---|---|
| 近 12 个月每月患者量 | 等于合成基准序列 | 以 `188 362 219 254 336 328 297 281 319 345 302 63` 为基准按月分配，当月预留 4 条「示例同款」病例后再补足 |
| 累计创伤 | 恰好 2380 | 先算 12 个月内创伤数，再回填 18 个月历史补足差额 |
| 24 小时表格 | 恰好 4 行示例病例 | 示例病例固定在今天 10:55 / 09:14 / 17:29 / 14:02，且**当月其余随机病例全部落在 24 小时窗口之外**（以 `now - 25h` 为上界生成） |
| 底部总数 | 4（创伤 3 + 胸痛 1） | 只有那 4 条为未闭环，其余历史病例全部闭环 |
| 年龄 | 60 / 13 / 40 / 88 | 出生日期一律取 1 月 1 日，保证 `calcAge` 结果精确等于目标年龄 |

月份序列以「当前月」为末位动态生成，因此在任何月份运行 `pnpm db:seed`，柱状图的 12 个数值都恒定等于合成基准序列（合计 3294），末位自动标记为「本月至今」。

## 后果

- 大屏在默认配置下与参考版面一致；接口验收把上述合成数值固化为回归断言（12 个月序列、累计创伤 2380、24 小时表格 4 行、底部统计 `创伤：3 胸痛：1`）。
- `screen_config` 让口径**可切换而不用改代码**：饼图聚焦病种、12 个月按创建时间/到院时间统计，都是配置项，已接入后台「大屏配置」页。
- 代价：演示数据是**合成且自洽**的，由构造规则决定，不代表真实业务分布。用于演示、培训、验收、联调足够，不用于数据分析结论。

## 后续

接入真实数据时口径无需改代码：只需调整 `ScreenService.buildPie()` 的 WHERE 条件并把 `pie_disease_code` 置空即可切换为全病种口径，前端不受影响。生产口径以使用方书面确认为准。
